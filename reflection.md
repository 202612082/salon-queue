Reflection — Salon Queue Management System

Building the Salon Queue Management System with a clear specification structure (AGENTS.md, docs/01-brief.md, docs/02-screens.md, and docs/03-flows-rules.md) made the implementation smooth from start to finish. Because the screen layouts, queue rules, and bilingual (EN/GU) expectations were defined upfront, the agent generated the application cleanly across all screens without needing retry prompts or major course corrections.

One assumption that went wrong at the end was expecting the final completion step to have already published a live public URL automatically. When I checked for the hosted link, I noticed the app was not yet live on the internet and had to manually connect the GitHub repository to Vercel, trigger the deployment, and add the live URL to the top of README.md. A common limitation with coding agents like Google Antigravity is that they can prepare project files and build steps locally while stopping short of live cloud hosting setup or external dashboard actions unless explicitly prompted to verify deployment and surface the live link. To prevent this gap in future builds, I would keep a dedicated deployment-and-verification step in my workflow and prompt the agent explicitly to check hosting readiness, verify the live URL, and place it at the very top of README.md before wrapping up.
